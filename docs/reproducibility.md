# Reproducibility Guide

VisionGuard separates tracked source/configuration from ignored local models and generated outputs.
Commands in this guide are run from the repository root.

## Reference environment

The recorded Phase 10 benchmark environment was:

| Component | Version / value |
|---|---|
| OS | Windows 10 |
| Python | 3.11.16 |
| PyTorch | 2.11.0+cu128 |
| CUDA runtime reported by PyTorch | 12.8 |
| GPU | NVIDIA GeForce RTX 4060 Laptop GPU, 8187.5 MiB |
| Transformers | 4.57.6 |
| Ultralytics | 8.4.151 |
| PaddleOCR | 3.7.0 |
| NumPy | 2.3.5 |

Compatible newer dependency versions may behave differently. Preserve an environment snapshot with
each formal experiment instead of treating this table as a universal lock file.

## Installation

Python 3.10 or newer is required. Python 3.11 is the verified environment.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
```

The project intentionally keeps one OpenCV distribution:

```bash
python -m pip uninstall -y opencv-python opencv-python-headless \
  opencv-contrib-python opencv-contrib-python-headless
python -m pip install --no-deps opencv-contrib-python==4.10.0.84
python -c "import cv2; print(cv2.__version__, cv2.__file__)"
```

Ultralytics declares `opencv-python` by package name, so `pip check` reports it missing even though
`opencv-contrib-python` provides the required `cv2` functionality. This packaging warning is kept
visible rather than hidden with a fake package.

## Public synthetic fixtures

Tracked fixtures are generated by repository scripts and contain no private publishing material:

```bash
python scripts/create_vlm_eval_samples.py
python scripts/create_ocr_smoke_images.py
python scripts/create_smoke_dataset.py
```

They create:

- `data/vlm_eval/`: three images and a tiny moderation manifest.
- `data/ocr_smoke/` and `data/ocr_eval/`: rendered OCR fixtures and GT.
- `data/visionguard_smoke/`: geometric YOLO fixtures and labels.

These samples validate engineering paths only. Do not use them for a model-quality claim.

## Models and local overrides

Model weights and caches are deliberately ignored.

1. Put a compatible YOLO checkpoint at `checkpoints/yolo26.pt`, or copy
   `configs/detector.yaml` to ignored `configs/local_detector.yaml` and edit `model_path`.
2. `configs/vlm.yaml` uses `Qwen/Qwen3-VL-2B-Instruct`; the first run may download it into the
   ignored artifact cache.
3. To use a local VLM directory, create ignored `configs/local_vlm.yaml` from `configs/vlm.yaml` and
   change `model_name_or_path`.
4. For the API, copy `configs/api.yaml` to ignored `configs/api.local.yaml` and point its service
   entries at the local detector/VLM overrides.

Never commit access tokens, private model paths, or downloaded weights.

## Determinism and seeds

- Detector training configuration records seed 42 and a deterministic option.
- Text splitting/training defaults to seed 42.
- Benchmark manifests are shuffled with a configured seed.
- Routing and fusion are deterministic for fixed structured inputs.
- Local VLM generation uses temperature 0, but GPU kernels and model/runtime versions can still
  introduce differences.

Always preserve the resolved config, code commit, environment, manifest, checkpoint identifier, and
prompt/policy versions with a result.

## Minimal reproducible flow

Train the small text baseline:

```bash
python scripts/train_text_baseline.py --config configs/baseline_text.yaml
```

Run one cascaded review after configuring local models:

```bash
python scripts/run_cascaded_pipeline.py \
  --image data/vlm_eval/risky.png \
  --detector-config configs/local_detector.yaml \
  --vlm-config configs/local_vlm.yaml
```

Start the API with a local API override:

```bash
python scripts/run_api.py --config configs/api.local.yaml
```

Run a small routing/fusion evaluation:

```bash
python scripts/evaluate_fusion.py \
  --mode cascaded \
  --manifest data/vlm_eval/manifest.jsonl \
  --detector-config configs/local_detector.yaml \
  --vlm-config configs/local_vlm.yaml \
  --output artifacts/fusion/my_evaluation
```

## Artifact structure and overwrite policy

Generated data is organized below `artifacts/`:

```text
artifacts/
├── baseline/<experiment>/
├── experiments/<detector-experiment>/
├── vlm/<experiment>/
├── pipeline/<run-id>/
├── routing/<experiment>/
├── fusion/<experiment>/
├── benchmarks/<experiment>/
└── error_analysis/<experiment>/
```

Evaluation and analysis commands expect a new or empty output directory and reject accidental
overwrite. Use a meaningful new experiment name instead of deleting evidence from an earlier run.
Raw artifacts can contain source paths and model identifiers; they remain local and ignored.

## Replaying without models

Routing/fusion/error-analysis replay consumes stored structured records:

```bash
python scripts/replay_error_cases.py \
  --records artifacts/fusion/my_evaluation/records.jsonl \
  --output artifacts/error_analysis/my_replay
```

Replay reports `models_executed=false`. It is suitable for policy changes that only depend on saved
signals, but cannot evaluate a new model or produce missing evidence.

## Verification

```bash
pytest -p no:cacheprovider
ruff check src scripts tests
ruff format --check src scripts tests
python -m compileall -q src scripts tests
git diff --check
python -m pip check
```

Real-model smoke tests are separate from unit tests because they require local weights, Paddle model
caches, a compatible GPU environment, and substantially more time.
